| 项目 | 实现与验收 |
| --- | --- |

| 单一元信息源 | manifest 维护名称、描述、匹配范围、权限、连接域和资源名；构建脚本生成完整头部并注入版本、仓库与 SHA-256；测试覆盖元信息注入拒绝、资源名同步和失败时保留输出。 |

| 可访问性 | axe 检查全部违规，无忽略规则；覆盖初始页、官方助手、总览、列表、十人详情的概要/伤害/技能、搜索、收藏备注、常看玩家、海克斯强化和英雄推荐。数据页同时检查 1280px 和 390px。 |

| 发布流程 | 串行处理发布：上传草稿 Release 资产 → 更新 UI 备用分支 → 公开 Release；拒绝覆盖已公开版本；记录备用分支原提交与 UI SHA-256。 |

## 外部事项与限制

- 没有配置 GreasyFork token、脚本 ID 或自动发布 job；现有 namespace 保持安装身份兼容。
- 没有修改远端 `ui` 分支 ruleset。需要仓库管理员在 GitHub 上单独配置允许的写入身份和强推范围；本地审计输出不等于分支保护已生效。
- 发布顺序为开发分支 CI → 推送 tag → 等待 Release 资产公开并校验 → 快进 master。直接提前更新 master 仍会产生资源尚未上传的时间窗口。
- 可变 `ui` 备用源可能与旧壳哈希不一致；加载器继续拒绝执行不匹配的 UI。
- package 与安装脚本使用 2.17.0，对应版本 UI 作为独立 Release 资产分发。
- E2E 使用仓库 sample 数据扩展与合成 Cookie/SDK；真实 WeGame 登录与脚本管理器沙箱需在对应环境单独验收。
