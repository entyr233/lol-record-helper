# 本人历史段位与胜点走势

## 使用

1. 在掌盟记录请求期间打开本人角色的历史段位页，导出 HAR 文件到电脑。
2. 安装重新构建的 `dist/userscript/lol-tft.user.js`，刷新 WeGame 页面。
3. 打开自建面板，点击“我的战绩”，展开总览下方“本人的历史段位与胜点走势”。
4. 导入 HAR，核对来源角色、大区和采集时间。存在多个记录时可以选择角色。
5. 确认本人记录后，查看赛季表格、排位模式筛选、走势图和逐场明细。

导入不依赖掌盟的分享或复制链接入口，也不需要在代码中填写 Cookie。文件内容在浏览器本地解析；只保留展示所需的数据与当前页面刷新使用的 scene，不写入浏览器存储或项目源文件。

## 数据与身份

导入只处理掌盟历史段位及用户资料的成功响应。角色名称通过请求 scene 与资料中的具体大区角色 scene 严格对应；不能用档案默认昵称代替具体角色名称。没有捕获资料时明确显示未识别角色，由用户核对采集来源。

掌盟记录和 WeGame 当前账号没有自动身份关联。本人拥有多个账号或大区时，也需要核对来源。导入快照展示采集时的数据，不代表今天的实时段位。

走势图按照掌盟返回的段位轴与胜点绘制，升段后胜点从较低数值开始时不会误画成掉分。缺失统计显示未提供，不填充为零。只有一个走势点时保留该点，不补造历史。

## 刷新

只有点击“从掌盟刷新此记录”才请求固定接口 `POST https://mlol.qt.qq.com/go/battle_info/get_rank_trend`，请求使用导入记录中的 scene。

刷新是否成功取决于访问参数有效期与掌盟权限。失败时继续显示导入快照。切换角色、取消等待或离开页面后，迟到响应不能覆盖其他记录。

- 本人记录只用于本地验证，没有写入测试样本、源文件或文档；测试使用合成身份与数据。
- 完整测试：35 个文件、453 条测试通过。
- `npm run build:all` 通过，包含类型检查、脚本构建、独立网页构建。
- 本轮没有在线提交用户的 scene，也没有验证掌盟在线刷新结果。

官方页面结构依据为 `https://lol.qq.com/m/zmlolzone/page/tier-detail/` 当前公开脚本；用户提供的本地响应结构与页面字段一致。
