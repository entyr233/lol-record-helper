# 网页性能与缓存

页面优先复用已经加载的数据，搜索直接在内存中筛选；静态资料与需要登录的玩家战绩分别管理。

## 缓存范围

| 数据 | 存储位置 | 保留规则 |
| --- | --- | --- |
| 英雄中文名 | 内存、一个固定 localStorage 条目 | 24 小时内重开页面直接复用；过期时先显示已有名称，再请求更新并覆盖原条目 |
| Data Dragon 版本号 | 内存、一个固定 localStorage 条目 | 12 小时有效，并发检查共享一次请求 |
| 英雄推荐详情 | 内存、localStorage | 当前使用的数据版本，最多 20 条；序列化 JSON 文本按每字符 2 字节估算，总预算 512 KiB；12 小时过期 |
| 原始战绩页 | 内存 | 最多保留 8 个玩家的已完成缓存，每人最多 20 页，每页 10 场；30 秒过期 |
| 图标 | 浏览器图片缓存 | 页面使用图片 URL 与懒加载，不另存一份 Base64 |

推荐详情在每个数据版本首次访问时恢复缓存，清理旧版本、过期和超预算的条目；之后复用内存数据。写入新详情前先清理，不逐个累积历史版本。这里的文本预算不代表浏览器实际磁盘占用或 JavaScript 对象的堆大小。

战绩缓存的清理在访问和请求完成时执行，不增加后台定时器。正在等待的请求继续共享，到请求完成后再应用玩家数量上限。收藏、搜索记录和账号设置不参与缓存淘汰。

推荐详情整体替换，使用 `shallowRef`，避免给只读的嵌套数据创建深层响应式代理。

## 验证

在已有测试文件中补充 5 项回归检查，覆盖重开页面复用、过期名称更新、并发版本请求、推荐详情数量与容量限制、战绩缓存数量限制。全量单测与 Chromium / Firefox / WebKit E2E 均通过，lint、类型检查和生产构建通过。

以上验证确认请求复用和缓存边界，没有测量真实账号与真实网络下的端到端延迟。首次下载、首次打开未缓存详情以及战绩接口响应，仍受网络和服务端耗时影响。
